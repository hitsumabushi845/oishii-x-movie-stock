# リファクタリング・デザイン改善記録

## 調査範囲

フロントエンド全モジュール、Pythonの収集・マージ・入出力・CLI、テスト、データとスキーマ、Vite設定、GitHub Actions、READMEと既存設計を確認。

現在のデータは297件。美味しい曖昧245件、美味しい贖罪17件、美味しい水玉26件、OISHII.inc 9件。最大ファイルはaimai.jsonの141,203 bytes。フレームワークの導入やAPI並列化より、不要な再計算・再描画・初期通信と、読み込み失敗時の扱いが今回の改善対象。

## 変更

### Web

- `main.ts`を起動処理に絞り、画面制御を`app.ts`、データの再利用を`archive.ts`、URLの読み書きを`url-state.ts`に分離。
- グループごとの取得Promiseを共有。失敗したPromiseは破棄して再取得可能にした。
- 並び順と統計をグループ読み込み時に計算。検索は遅延ロードし、同じ検索語でのフィルタ・並び順変更には検索結果を再利用。
- 150msのdebounceと日本語変換イベントに対応。世代番号で、古い読み込みの成功・失敗が現在の表示を書き換えないようにした。
- URLに並び順も保存し、戻る・進むで検索・フィルタ・グループと合わせて復元。
- 一覧内に残る同じ投稿DOMを再利用。位置が変わらない埋め込みはDOMから外さず保持する。並び替えでiframe自体が移動する場合の再読み込みはブラウザに依存する。
- Xスクリプトと投稿の生成にそれぞれ15秒の待機上限を設定。失敗時にXへのリンクと再試行方法を表示し、閉じた投稿への新しい埋め込み要求を抑制。
- 不正な動画長・日時・tags・重複ID、グループ定義を読み込み時に検査。日時はUTC・ミリ秒精度に統一。
- グループ選択ボタンを作り直さず選択状態だけ更新し、キーボードフォーカスを維持。

### デザイン

- 白・淡いブルーを基調とするライブラリ。PCの左側にグループ選択、右側に見出し・検索・投稿一覧を配置。
- 投稿本文を2行まで表示し、展開時は全文を表示。日付と尺は補助情報に整理。
- 大きな総再生時間表示、尺メーター、各行の登場アニメーションを廃止。
- 外部Webフォント3書体を端末の日本語ゴシック・システム書体に置換。
- スマートフォンではグループ選択を横スクロールで上部に配置。ライト・ダーク両対応。
- 空結果・読み込み・再試行・手動の追加表示を設け、操作結果と次の操作を明示。
- グループ色に重ねる文字は黒・白のコントラストを比較して選択。
- X埋め込みの最大幅を保持し、iframeの`color-scheme`を調整。ダークテーマで余白が白く描画される問題を修正。
- 比較ページで選定したB3ロゴをSVGで組み込み。小サイズ用のシンボルから明暗対応SVG faviconと互換用PNGを作成。
- ロゴの比較ページは`web/design/logo/`に保存。開発サーバーの`/design/logo/`で確認でき、productionビルドには含めない。

### Python

- `model_dump_json()`からJSONを再解析する往復を`model_dump(mode="json")`に置換。
- JSON文字列全体の`+00:00`置換を撤去。日時以外の投稿本文・tagsが書き換わる不具合を修正。
- マージ比較時のモデル辞書化を直接比較に変更。
- 先頭動画の抽出に中間リストを作らず、最初の該当要素を取得。
- `from:`に指定されたアカウントで投稿URLを生成。従来は他グループでも既定のアカウントが使われた。
- 同じページカーソルが再登場したら例外で停止。部分的な取得結果を完全なアーカイブとして返さない。

GitHub Pages・データ形式・週次更新の構成は継続。取得処理の2秒待機と直列実行はレート制限対策として維持。

## 計測

`pnpm build`のVite出力。gzipは圧縮後のサイズ。

| 対象 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 初期JS | 37.43 KB | 17.24 KB |
| 初期JS gzip | 13.42 KB | 6.68 KB |
| 初回検索時の追加JS gzip | 初期JSに同梱 | 8.73 KB |
| CSS gzip | 2.81 KB | 2.75 KB |
| 外部Webフォント | 3書体 | 0 |

初期JSの圧縮サイズは約50%減少。検索後のJS合計は15.41 KB gzipとなり、機能・検証追加分により従来より増加している。初期表示の必要量と総量を分けて評価する。

Chrome上で245件のaimaiデータを使用。「ライブ」で検索し、1分以上・昇順/降順を交互に200回×5セット実行。5セットの1回平均の中央値は、従来の検索＋フィルタ＋並び替え＋統計計算が約1.58ms、検索結果の再利用後は約0.008ms。

この比較はウォーム状態で同じ検索語を再利用する操作に限る。DOM描画、初回検索ライブラリの取得・索引生成、通信、X埋め込みは含まない。ページ全体の表示速度やCore Web Vitalsの改善率を示す測定ではない。

## 制約

動画自体の可用性・通信時間・プレイヤー内部の動作はX側に依存する。大量データを読み進めた場合は表示済みDOMが増える方式を継続している。現状の件数では仮想スクロールを追加する複雑さを避け、追加読み込みを20件単位としている。

過去に生成された動画JSONのURLは一括書き換えしていない。
